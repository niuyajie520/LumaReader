# LumaReader 1.6.0 · B66 性能体检与修改报告

基线：此前交付的完整 1.5.0 B65 源码。目标：减少 App 与自有语音服务的持续 CPU、内存和不必要的图形工作，降低与浏览器争抢资源的机会。本包仍是待 Mac 验证的候选版。

## 主要发现与处理

| 范围 | 源码证据 | 本次处理 |
|---|---|---|
| 作文保存 | 每次 DELETE 全表并重写全部作文 | 事务内比较记录，只编码/更新变化记录，定向删除；其他 SQLite 连接修改时通过 data_version 使缓存失效 |
| 学习 JSON | 内容相同仍原子重写文件 | 使用摘要及文件修改时间跳过相同内容写入，避免额外保留一份大编码缓冲区 |
| 封面 | 缓存只限制 600 张，退屏卡片仍持有图片 | 缓存预算 64 MiB、最多 120 张，按像素估算成本；退屏释放局部状态；同时解码最多 2 张、重复请求合并 |
| 封面色种索引 | 每张封面都可触发全索引写入，并发写可能乱序 | 500ms 合并、单串行队列写；切换目录时清除旧索引状态。色彩算法本身不改 |
| 静态主题背景 | 与听写输入/计时父状态关联，可能重复评估复杂 Canvas | 保持全部绘图代码原样，使用 Equatable 子视图隔离静态输入；不删除主题、模糊、玻璃或动效 |
| 阅读准备 | 预备快照可能在切后台后仍产生图形工作 | 切后台和内存压力时释放预备快照/搜索索引；高热和后台不预备新快照；翻页时仍保留原动画路径 |
| 原生悬停控件 | 活跃时每 100ms 都调用窗口控件整理 | 保留鼠标采样精度，但只有显隐/尺寸/安全区/全屏状态变化时整理控件 |
| 等待听写结束的任务 | 每 250ms 轮询等待 | 改为可取消的事件唤醒；退出听写、后台暂停、任务取消时安全恢复等待方 |
| ONNX | 原来的 OMP 环境变量不能保证限制 ONNX 自己的线程池 | 固定 kittenml 0.9.7 的 ONNX 路径使用 2 个 intra-op 线程、1 个 inter-op 线程、顺序执行、CPU provider；关闭线程空转与 CPU arena/内存模式保留 |
| 语音进程 | 普通后台和长时间闲置可能保留模型 | 切后台 30 秒释放自有进程；自有服务空闲 180 秒退出；系统内存压力时回收闲置模型；保留用户选择，不强制切换成 Nano |
| 音频缓存 | WAV 可无限积累 | 目标预算 256 MiB、30 天过期清理；保护近 5 分钟文件、链接及非哈希命名文件；缓存直接播放也更新使用时间 |
| 预读 | 可预生成后面 10 个单词 | 限制为后面 3 个，当前词依然优先。暂停取消未执行任务 |
| 音频重复播放 | 每一遍重读/解码文件；频繁重连音频图 | 一次解码用于本次所有重复；格式相同时复用音频图；播放代次校验避免旧任务影响新播放 |
| 派生词汇索引 | 离开学习仍保留可重建索引 | 离开学习/内存压力时释放派生缓存，原始词库、会话和进度保留 |

NSCache 是软预算，不是 App 进程内存的严格上限。正在显示的封面、WebKit、音频缓冲和模型有各自占用。音频缓存清理只在服务空闲时执行，最近文件的保护期可能让磁盘暂时超过目标预算。

## 重播与快捷键

手动重播不再因暂停状态直接返回；暂停后点重播会恢复当前练习并播放。生成同一个词时保留现有推理，但更新最新的速度/重复次数，不再忽略慢放操作。旧任务通过播放代次校验退出；自有进程闲置退出后，下一个未缓存请求会重新检查/启动服务。

| 快捷键 | 作用 |
|---|---|
| ⌘R | 重播当前词 |
| ⇧⌘R | 单次慢放 0.75× |
| ⌥⌘P | 暂停 / 继续 |
| ⌥⌘M | 显示 / 隐藏中文 |
| ⌘/ | 首字母提示 |
| ⌥⌘← | 返回上一个已完成单词，纠错中仍遵循原限制 |
| Return | 原有提交答案 |
| ⇧⌘/ | 快捷键帮助 |

快捷键只监听当前练习主窗口的本地事件；不拦截其他窗口、浏览器、弹窗和输入法组合文字。⌘H 恢复给 macOS 隐藏应用。可在“更多 → 模块与同步”找到帮助入口，或右键倍速菜单查看。

## 🛡️ 保留与边界

已按 B65 逐字节比对：Theme.swift、MonetTheme.swift、LumaDesignTokens.swift、StudyAppearance.swift、NativeWindowControls.swift、Reader.js、Reader.css、CloudFileManager.swift、DictationThemeErrorAccent.swift、DictationEngine.swift、StudyPromptView.swift 保持一致。全部背景绘图路径/颜色/参数逐字一致，只包裹了静态子视图。顶栏七键、红黄绿位置、听写输入布局/判题、进度条、错误动效、三级分类和写作高亮没有重排。

不改变 Safari 或其他进程的设置、优先级和页面。只降低自己的 Python 服务优先级。依赖版本保持原有固定版本，没有删除 Kitten Micro/Nano 或学习文件。

## 验证证据

- 18 项 Python 测试通过：队列边界/优先级/取消、定向删除 Kokoro、缓存容量与文件保护、ONNX 配置与异常恢复、本地真实 HTTP 请求/缓存重复使用，以及 Swift 内嵌 UPSERT SQL 的 SQLite 行为。
- HTTP 测试使用真实 HTTP 服务、队列、磁盘 WAV；推理使用确定性替身，未下载/试听真实模型。
- 独立 SQLite 工作负载：1,200 条记录，12 次保存，每次仅修改一条。旧策略 28,800 次行变更，新策略 12 次。测试机一次观察的事务耗时中位数约 6.201ms → 0.056ms。这只验证 SQLite 操作策略，不包括 Swift 编码、UI、实际用户数据或 Mac 硬件，不是整体 App 加速倍数。
- Swift 语法解析、源码完整性、诊断静态约束、AI 资源、Shell 语法、diff 空白检查通过。
- 新增 Mac 原生回归测试：无变化保存、未修改行身份、外部连接使缓存失效、删除、重复 JSON 保存、快捷键分配。原生验证脚本现同时执行 App 和 StudyCenter 包测试。

## 🔴 未验证与权衡

没有 Apple macOS SDK/Xcode，因此本次没有原生编译/签名/安装成功记录，没有执行新增原生测试，也没有听到实际重播。没有 Instruments、Energy Log、GPU/WindowServer 或真实浏览器多标签 A/B 数据，不能承诺整机百分比改善或“十几个网页绝不卡”。此前鼠标点击失效的唯一根因也仍未由用户 Mac 记录确认。

两个推理线程和关闭内存 arena 会改变生成延迟/内存取舍；模型闲置释放后，首次未缓存单词需要重新加载模型。缓存命中的音频仍直接播放。以上需要在用户 M4 Air 上验证。

历史作文仍按既有会话/统计结构加载；本次没有把完整历史改成分页架构，以免破坏现有跨模块恢复、历史编辑和统计。先解决确认存在的全量重写与缓存问题；若实测历史数据仍是内存大头，再用实测证据继续调整。

## Mac 验证顺序

1. 运行 Verify-LumaReader.command，确认 App 与 StudyCenter 两套原生测试及 Release 构建成功。
2. 听写当前词：播放中连点重播、播放结束重播、暂停后重播、生成过程中点慢放、切到下一词、切后台 30 秒后返回重播。
3. 验证快捷键只在听写窗口生效，⌘H 能隐藏 App，写作/浏览器键盘输入不受影响。
4. 用相同书籍/词库、相同浏览器标签，分别观察前后台 5 分钟的主 App CPU/内存、自有 Python 进程、系统内存压力与热状态；不要把整个 Safari 的 WebKit 占用算到本 App。
5. 如再次出现鼠标点击失效，运行 Diagnose-Mac.command，提供进程/窗口诊断；安装或原生测试失败则提供日志。
